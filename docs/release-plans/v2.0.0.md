# rules_wasm_component v2.0.0: release plan (draft)

Status: draft, work in progress. Nothing here is released or claimed to work
end to end. Scope lives in rivet (`release: v2.0.0`); `rivet release status
v2.0.0` is the readiness query. Planned 2026-11-19 against the North Star in
pulseengine.eu `data/north-star.toml`.

## What this release does and does not move

v2.0.0 moves **zero North Star indicators** directly. It is enablement: it
makes the O2 and O5 indicators reachable for Bazel product teams and backs
this repo's own claims with checks that can fail. The indicators named below
are the ones each bet prepares; the "local proxy" is what this release can
actually measure.

v2.0.0 is a major release because MoonBit support was removed (#639, DD-005).

## Order

1. Bet 2 spike first (days): plant bad inputs against the existing
   `//examples/pipeline_attestation` attested output and see which ones
   `wasm_verify_chain` already rejects. Its result decides whether Bet 1 is
   evidence or a demo.
2. Bet 3 (gates the cut), Bet 1 and Bet 2 in parallel.
3. Bet 4 once Bet 1's target builds.
4. Bet 5 if time allows; it folds into Bet 1's AADL seam.

## Bet 1: one Bazel target from architecture model to evidence bundle

FEAT-006. `//examples/certifiable_chain:bundle`: `aadl_wit_library` (spar) ->
Rust component -> `wasm_optimize` (loom) -> `meld_fuse` -> witness coverage,
with `wasm_sign` / `wasm_attest` / `wasm_verify_chain` and a new
`wasm_evidence_bundle` rule. Tools come from the varve covalent layer, except
wsc and wasmtime, which the bundle manifest names as outside the layer.
`aadl_wit_library` gains a WIT provider so its output feeds bindgen (today it
returns only a tree artifact).

- Prepares: O2 ("consumer repositories whose latest release carries the full
  bundle and passes the verify command") and O5. Local proxy: the target
  exists and builds in CI.
- The bundle is **partial** until it carries all three O2 pieces: rivet trace,
  witness MC/DC report, sigil attestation. Today the rule set has no rivet
  toolchain and witness is wired for LCOV; both are open items, not assumed.
- Acceptance: `bazel build //examples/certifiable_chain:bundle` green in CI on
  linux and macos, and a test asserts the content: coverage above 0 on the
  fused module, attestation present and verifying, every manifest hash
  matching. `bazel cquery` shows spar, loom, meld and witness resolving to the
  varve layer.
- Kill: any single seam yields hollow evidence (bindgen cannot consume the
  AADL-generated WIT, meld cannot fuse the example, or witness reports 0 on
  the fused module). Then ship Bet 3 alone and record the gap.
- Depends on: meld (meld#479 class of composite issues), witness (relay#202:
  0 coverage on composed async pipelines), rivet (trace export for the
  bundle), sigil (verify semantics). Finishable here only as a partial bundle.

### Bet 2 spike result (2026-11-19)

Run on `//examples/pipeline_attestation:greeter_attested` (local build, macOS):

| input | `wasm_verify_chain` (wsc 0.9.2) | `wsc verify-chain` 0.12.1 |
|---|---|---|
| unmodified | pass | pass |
| attestation section deleted | fail | not run |
| signed, never attested | fail | not run |
| one bit flipped in the core module after attestation | **pass** | **pass** (identical output) |

`strict = True` also passes the flipped file. `require_signatures = True`
fails both files, because no key is passed, so it cannot separate them.
The attestation's recorded `output.hash` equals the sha256 of the file without
its attestation section (630a41bb… for the unmodified file, 4c80aca2… for the
flipped one). The mismatch is detectable from data already present, but
verify-chain does not check it: pulseengine/sigil#395. The chain JSON also
records absolute sandbox paths (same issue).

Consequence: Bet 2's kill criterion is met for verify-chain *alone*. Bet 2
proceeds only with its own content re-hash, plus a planted bit-flip control,
and `wasm_verify_chain` must not be described as tamper detection until
sigil#395 is settled. Bet 1 can start: it does not depend on verify-chain
catching content changes, as long as the bundle check does.

## Bet 2: a verify check that fails when any evidence is removed

FEAT-007. `wasm_evidence_verify_test`, with the checker written in Rust as a
WASI component run under wasmtime (no new Python). One planted control per
evidence piece in `ci-controls.toml`: attestation stripped, coverage report
removed, coverage report present but 0%, manifest hash altered, trace removed,
and one bit flipped in the component after attestation (the case
`wsc verify-chain` passes, sigil#395).

- Prepares: the O2 guard ("the verify command must fail when any piece of
  evidence is removed"). Local proxy: a repo-local verifier with one negative
  control per piece. It is not the org verify command; the bundle format must
  be agreed with that command's owner.
- O3 caveat: O3 counts proof-carrying repositories whose proof check is a
  required check; this repo is not one, so this moves no O3 number.
- Acceptance: the test passes on the Bet 1 bundle and every plant fails with
  a matching message.
- Kill: `wsc verify-chain` passes on a component with the attestation removed
  or an input tampered. Then the claim comes out of the docs and the finding
  goes to sigil.
- Depends on: sigil (wsc verify semantics), the org verify command's owner
  (bundle format).

## Bet 3: the release's own claims backed by checks that can fail

FEAT-008.

- `rivet validate` as a CI job, with a planted broken artifact.
- CI coverage, with `rivet: verifies` markers, for the four v2.0.0 artifacts
  still `implemented`: FEAT-003 / REQ-007 (`wit_from_component`), FEAT-004
  (varve toolchains), FEAT-005 (native loom).
- `//examples/component_import_example` and `//examples/pipeline_attestation`
  in CI.
- Checksum-pinned bazelisk in the remaining jobs that download
  `releases/latest`.
- The required-check list for main (owner sets it).

- Local proxy: required checks on main 0 -> N; v2.0.0 scope from 3 verified +
  2 accepted + 4 implemented (9) to 7 verified + 2 accepted.
- Acceptance: every check added to the required list has a plant that turns
  it red in CI, and `rivet release status v2.0.0` reports cuttable with each
  `verified` status backed by a marker on a step that runs in CI.
- Kill (observation): a required check whose plant does not turn it red, or a
  `verified` artifact whose marker points at a step that does not run on PRs.
  Either blocks the tag.
- Depends on: the owner (branch protection); rivet#1294 (markers in
  `.bzl`/`.bazel` are not scanned, so markers sit on workflow steps).

## Bet 4: an outside team builds the chain from a blank module

FEAT-009. A standalone consumer module with its own `MODULE.bazel` depends on
rules_wasm_component and builds the Bet 1 target; CI runs it against the
checked-out ruleset (linux and macos; varve ships no Windows binary). The four
bootstrap steps from #533 are removed or documented; `docs/migration.md`
covers the MoonBit removal and `docs/certification-pipeline.md` gets a
correct status table.

- Prepares: O4 ("merged pull requests per month by people other than the
  maintainer"). A precondition only: a reproduction report is not a merged PR.
- Acceptance: the consumer CI job is green, and a plant (a consumer missing
  one bootstrap step) fails with a message naming the step.
- Kill: no outside reproduction or issue within one varve layer after the
  release. Then stop investing in onboarding here and ask in #634 what blocks
  people.

## Bet 5 (stretch): AADL-to-WIT drift test

FEAT-010. `aadl_wit_diff_test` (#539 gap 1): regenerate WIT from the model and
diff against the checked-in WIT, with a planted drifted file.

- Local proxy only (same O3 caveat as Bet 2): "the WIT derives from the
  model" becomes a check.
- Acceptance: passes on `examples/spar_example`, fails on the plant.
- Kill: spar output is not byte-stable across layers.

## Left out

- O1 (runs on target): needs hardware runs and synth, kiln, gale and jess
  results; `synth_compile` building an ELF here is not that.
- kiln as the runner for our own gates (the O5 numerator): no kiln toolchain
  here yet.
- wsc into varve: needs its own review.
- wac 0.11 / P3 composition (#180), remote execution (#18), hermetic
  `wasm_tool_run` (#722), Go dependency resolution (#128), the OCI test (#680).
- Porting the existing Python CI scripts to Rust: queued as port candidates.

## How this plan was made

A planner pass proposed five bets from north-star.toml, the rivet state, open
issues, the v1.1.1 notes and a read of the repository. A separate checker
pass, given only north-star.toml and the draft, judged each bet. This
revision applies its findings: the zero-indicator statement, the O3 caveats,
content-asserting acceptance for Bet 1, one negative control per evidence
piece, observation-based kill criteria for Bet 3, and the Bet 2 spike before
Bet 1.
